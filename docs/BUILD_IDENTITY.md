# Build / Artifact Identity

FSTR Line packages embed Build Identity automatically. No manual version editing is required.

## Identity fields

Every packaged CEP artifact contains:

- product;
- version;
- artifact type;
- extension ID;
- full Git commit;
- Git state: clean or dirty;
- deterministic Build ID;
- declared host/runtime target;
- build toolchain record.

Build ID format:

    FSTR-Line@<version>+<12-char-commit>.<clean|dirty>.cep

## Generated metadata

Packaging creates:

- generated/build-info.json
- generated/build-info.js
- generated/build-info.jsx

The browser panel and After Effects host script load metadata generated by the same packaging run.

## Runtime proof

The panel Diagnostics view displays browser and host identity side-by-side.

If Build ID or Git commit differ, FSTR Line reports a Build Identity mismatch instead of silently claiming the artifact is verified.

The browser logs Build ID/commit/state to the CEP console. The host writes FSTR_LINE_BUILD with the same metadata to ExtendScript diagnostic output.

## Hashes

BUILD_MANIFEST.json contains SHA-256 and byte size for every production file.

The verifier also calculates and prints SHA-256 of BUILD_MANIFEST.json itself.

Build ID and artifact hash are deliberately separate identifiers.

## Clean-state policy

Dirty packages may exist for internal experiments, but verify:package and the clean development installer reject dirty artifacts.

Milestone, release and user manual-test evidence must use a clean Build Identity.
