## 3. Выбранный механизм и уже отвергнутые пути

Текущий кандидат: экспортированные **BEE_Callback_Insert / BEE_Callback_Remove**, которыми пользуется сам AE для цепочки сообщений UI. Регистрация не требует приватного указателя проекта. Обработчик обязан продолжать цепочку; простое `return 0` может подавить обработку AE. Указатели сообщений нельзя сохранять после callback или трактовать как публичные handles.

Dirty-only сигнал отклонён как самостоятельный источник повторных изменений: одинаковый dirty-флаг пропускает уведомление в исследованном setter. Рендер-очередь BEE не принята как надёжная доставка в UI; поиск неэкспортированной completion Connect больше не основной маршрут.

LLDB — только исследовательский инструмент. [Issue #3](https://github.com/ios3kov/FSTR-Line/issues/3) остаётся **open**: исторические таймауты/падения и завершение собственного тестового процесса с `-9` не закрыты последующими зелёными прогонами. Не возвращаться к бесконечной доработке LLDB вместо проверки настоящего callback без отладчика.

## 6. Следующий конкретный шаг

**Полная native-сборка на авторизованном Apple Silicon Mac с предоставленным SDK**, а не новый общий сборщик или повтор старого исследования. Сначала обычная сборка с выключенной частной регистрацией:

```sh
python3 -B research/ae-notifications/chain-probe/build_probe.py --sdk /path/to/ae25.6_61.64bit.AfterEffectsSDK
```

Проверить clean Git state, действительные SDK inputs, компиляцию/link, PiPL, архитектуру/экспорт entry point, подпись и Build ID. `build-record.json` пока должен сохранять `handoffApproved=false`, `AEGP_load=NOT RUN`, `SYNC-001=NOT RUN` до соответствующих реальных проверок. Успешный build не переименовывать в успешный host-test.

Далее контролируемый выключенный старт, затем отдельно исследовательский opt-in и минимальная проба без LLDB на одноразовом тестовом проекте: два изменения времени слоя без сохранения, script-origin, Undo/Redo, прозрачное прохождение цепочки, Stop/удаление только своей регистрации. Проверить реальные thread/lifecycle условия, а не выводить безопасность из `in_flight == 0`. Только после этого расширять покрытие на selection/reorder/context/закрытие и остальные поля/источники SYNC-001.

Если нужная Mac/AE-среда недоступна, зафиксировать точный блокер; не называть модельный тест реальным и не тратить следующий этап на общие сборщики. Согласованные требования не ослаблять: idle/wake только доставка, не источник; polling/revision/focus/self-events не замена настоящим AE-уведомлениям.
