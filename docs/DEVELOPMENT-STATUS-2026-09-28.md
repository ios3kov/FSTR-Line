## Текущий шаг — найден экспортируемый путь сообщений UI

База: `cfa8a1db2fcd576a0023cdee579c7f83c40d04e6`. Правила main перечитаны:
blob `701a8c1ae3acb4dbfe1d7eda94acbf8095b88608`.

В полученных библиотеках найдена пара BEE_Callback_Insert / BEE_Callback_Remove.
Сам AE использует её для подключения CallbackFromBEE, ведущего в обработчик UI.
Регистрация принимает обычный callback и данные клиента, возвращает отдельный ID;
для регистрации не требуется получать приватный указатель проекта или clone.
Это точный статический разбор, не подтверждение безопасного внешнего вызова.

Прослежены реальные цепочки: изменение времени слоя, флагов, порядка, выделения,
времени item и закрытие проекта -> BEE_Callback_UI_Submit -> штатный обработчик UI.
Проверены числовые коды сообщений и таблица переходов, а не только имена функций.
Этот путь выбран для следующей минимальной native-пробы вместо поиска
неэкспортируемой специализации completion Connect. Dirty-only кандидат остаётся отклонённым.

**Ключевой риск:** callback обязан продолжить штатную цепочку и сохранить её
результат. Простое возвращение 0 может отключить обработку самим AE. Native
forwarders и виртуальный переход Continue разобраны. Данные некоторых сообщений
лежат на стеке: сохранять их указатели после callback нельзя. Полнота доставки,
потоки, безопасное снятие callback и post-commit чтение ещё не приняты.

Проверено на исходных байтах: 25 тел функций / 7 472 позиции, семь BL-переходов,
экспорт пары регистрации, 12 имён сообщений и 15 веток обработчика UI.
Изменены только документация и evidence. Новых сборщиков, исправлений LLDB,
вызовов Adobe-кода или изменений продукта нет.
[Факты, ограничения и критерии native-пробы](TEST_RECORDS/BEE-CALLBACK-SOURCE-2026-09-30.md).

## Следующий шаг и ограничения

Минимальная AEGP-проба: прозрачная регистрация/отписка, повторное изменение
времени слоя, затем native/script/Undo/Redo. Callback сначала сохраняет работу AE;
событие ставит pending, чтение свежего состояния выполняется отдельно через
публичный API на потоке host. Idle не источник событий и не повод сканировать проект.

Архив SDK в этом runtime пока отсутствует; native-сборка и запуск AE не выполнены.
Новых отчётов с отдельными функциями не требуется: три библиотеки уже получены.
Проверка совместимости, lifecycle, всей матрицы SYNC-001 и производительности
остаётся NOT RUN/BLOCKED. Issue #3 и исторические runtime FAIL не закрыты.
Плагин пользователю не передаётся, готовность синхронизации не объявляется.
