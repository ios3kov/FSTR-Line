## Текущий шаг — прямой источник событий вместо доработки LLDB

База: `cabf37d11571722f8392035803bd06d7dd689508`. Правила main перечитаны:
blob `701a8c1ae3acb4dbfe1d7eda94acbf8095b88608`.

Разделены источник уведомлений и доставка в основной поток. Для минимального
доказательства больше не требуется превращать BEE render queue в UI-dispatcher.
Проверяется связка: настоящий callback AE -> pending -> штатный AEGP wake/idle
callback -> чтение свежего состояния публичным API. Idle не служит источником
изменений: без события нет чтения проекта и повторного самозапуска.
Это выбранная схема проверки, не реализованная или принятая синхронизация.

Первый кандидат — уже найденный ConnectDirtyStateChangedSignal. Сразу проверить
повторное изменение уже dirty-проекта; если сигнал только о первом изменении,
отклонить его как основной источник. Затем отдельный кандидат Undo-completion.
Ни один из них заранее не считается покрывающим selection/playhead/context.
Без доказанных ABI/владения приватные функции не вызывать.

Вместо очередного запроса восьми функций подготовлена однократная передача
копий BEE.dylib, AfterFXLib и dvacore. Copy-Research-Modules.command не запускает
AE/LLDB, не читает проекты, не устанавливает и не отправляет ничего по сети.
Полные модули здесь отсутствуют. После их получения можно самостоятельно
прослеживать вызывающие функции и реализации, без ручного сбора каждой порции.

Локально: восемь проверок копирования на собственных файлах PASS; bash syntax PASS.
Проверки точного commit на Linux/macOS и hash передаваемого файла фиксируются в PR #2.
[Решение, источники, критерии остановки и границы проверки](TEST_RECORDS/DIRECT-SUBSCRIPTION-FOCUS-2026-09-30.md).
