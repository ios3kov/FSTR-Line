## Текущий этап — проверка завершения основного диагностического запуска

База: `3daca55bdc72b80a9d11591db416ebd583cbaaa5`. Правила main:
blob `701a8c1ae3acb4dbfe1d7eda94acbf8095b88608`.

В actual-source тестах воспроизведены ложный PASS после ненулевого выхода LLDB,
ложный PASS после таймаута с последующим exit 0 и отсутствие очистки при ошибке
ожидания ready. Основной `runtime_probe.py` теперь проверяет и завершение
отладчика, и подтверждение controller. Таймаут/принудительная очистка не могут
стать PASS. Очистка охватывает ожидание подключения; PID After Effects не завершается.

Отдельный `observer-parent.json` сохраняет решение, run ID, hash плана и
результата, код выхода и признаки таймаута/очистки. Исходный `result.json` не
переписывается. Успешный архив включает оба отчёта. Ошибки оставляют рабочий
каталог с диагностикой. Автовозобновление требует подтверждённого чистого
завершения отладчика; старые или аварийные отчёты не используются для него.

Локально 23 проверки PASS: 15 новых и восемь существующих, включая обновлённую
проверку безопасного возобновления. Есть настоящие собственные дочерние процессы
и файловый IPC; это не AE и не LLDB. Полного checkout здесь нет из-за DNS.
В macOS CI добавлены пять запусков actual packaged parent с настоящим LLDB
в каждом push/PR workflow. Итоги относятся только к содержащему commit и
фиксируются в PR #2 вместе с hash архивов. Таймауты и обязательные проверки не ослаблены.

[Воспроизведение, приёмка и ограничения](TEST_RECORDS/RUNTIME-PARENT-EXIT-2026-09-30.md).
Пользовательский диагностический пакет не передаётся; действий пользователя не требуется.

## Подтверждённый разбор очереди и проектов

`FSTR-AE-Queue-qk6xsvhj`: 19 тел, 26 успешных команд, 5 029 четырёхбайтовых
позиций; контрольные суммы и связь с пакетом `eef15f5` проверены. Повтор не нужен.
По коду этой сборки: вставка в конец/удаление с начала под блокировкой; вызов
после удаления и снятия блокировки; отмена может очистить очередь; проверка
project ID после вызова не является pre-call защитой. Глобальный порядок
завершения, единственный поток исполнения и доставка не доказаны.

Основной проект, clone и faux имеют отдельное хранение/создание; полная
десериализация направлена в clone. Getters не дают доказанного внешнего владения.
RegisterListener хранит callback в другой структуре; связь с очередью, emitter
и безопасное время жизни не установлены. 50 строк `.long` декодированы отдельно;
четыре байта таблицы CommandType отсутствуют. Generic callback нельзя приписывать
ветке пропуска при загрузке без этих байтов.

[Порядок, отмена и clone](TEST_RECORDS/QUEUE-ORDER-CLONE-2026-09-30.md).

## Незакрытые условия и следующий шаг

**SYNC-001: production integration BLOCKED/NOT RUN.** Проверить новый parent на
точном пакете в macOS CI. Исходный таймаут #3 остаётся незакрытым; перед следующим
real-AE handoff нужны актуальные проверки всей используемой цепочки запуска.

Далее: вызывающая сторона и назначение потока callback очереди `+0x40`;
контракты BEE_QueryProject / BEE_GetCurrentConstProject / BEE_ProjectSetContext;
таблица CommandType; emitter и время жизни WorkQueue-подписчика. Сбор должен
закрывать эти пробелы, не повторять полученные отчёты.

Поток/порядок, связь с активным UI-проектом, безопасная подписка/отписка,
post-commit доставка, пропуски/повторы, закрытая панель и нагрузка без отладчика
не приняты. Native harness допустим только после доказательства безопасных
контрактов. LLDB/polling/idle/focus/self-events не заменяют источник уведомлений.
